This is an ordinary documentation page. The heading above, this paragraph, the
code block below — all standard Fumadocs, exactly what you would write in any
other docs tool. The difference shows up when you reach for `<Spread>`.

## Flowing prose

Wrap any Markdown in `<Spread>` and the prose flows around a figure, like a
magazine column. Notice the formatting survives the layout:

<Spread orb side="right" width="42%">
Everything inside a Spread is plain Markdown, so **bold**, *italic*, and inline
`code` all keep working while the text flows around the figure to the right.
The engine measures every run of text with [pretext](https://github.com/chenglou/pretext)
using nothing but canvas arithmetic — no `getBoundingClientRect`, no reflow —
then positions real, selectable DOM text on both sides of the obstacle at once.
That last part is something CSS Shapes cannot do: it only ever wraps on a single
side. Here the column genuinely narrows as it passes the orb and widens again
below it, and the words you are reading remain ordinary text nodes that a
crawler can index and a screen reader can announce.
</Spread>

## How it stays fast and accessible

The server renders the prose above as a normal paragraph first, so search
engines and assistive technology always get clean text in reading order. After
the page hydrates, the client measures and repositions that same text into the
flowed layout. Same words, just placed differently — progressive enhancement,
not a hidden copy.
